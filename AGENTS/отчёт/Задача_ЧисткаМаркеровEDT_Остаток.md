## 1. Требуется прогон «выгрузка → загрузка» на тестовой базе (обязательно до поднятия версии)

Что менялось в поведении и требует проверки:

- ядро выгрузки `DataProcessors/ВыгрузкаЗагрузкаДанныхXMLСФильтрами/ObjectModule.bsl`:
  состав колонок регистров берётся из `НаборЗаписей.Выгрузить()` (было — пробный запрос
  `ВЫБРАТЬ ПЕРВЫЕ 1 *`); обход ссылок объектов — через объектную модель и кэш колонок
  (`ПостроитьКэшКолонокОбъектов` + `ОбработатьОбъектПоСсылке`), состав колонок кэшируется
  одним пакетным запросом `ВЫБРАТЬ ПЕРВЫЕ 0 *`;
- `ЗаписьКонстанты`: отбор констант проверяется кодом (`СоответствуетОтборуКонстанты`)
  вместо запроса;
- формы `ТБ_ИсточникиДанных/ФормаЭлемента` и `ТБ_СопоставлениеОбъектов/Форма`:
  разбор/запись XML перенесены на сервер, путь к файлу передаётся строкой;
- `НачатьПомещениеФайла` → `НачатьПомещениеФайлаНаСервер`;
- обработчики сопоставления в `ТБ_СопоставлениеОбъектов` исполняются в безопасном режиме
  (`УстановитьБезопасныйРежим`).

Чек-лист прогона:

1. Иерархические справочники: `Родитель`, `Владелец`, подчинённые справочники — порядок
   объектов в XML (зависимый раньше зависящего) не нарушен.
2. Документы с движениями; регистры накопления / сведений / расчёта;
   **регистр бухгалтерии с субконто и корреспонденцией** — состав колонок совпадает с прежним.
3. Пустой регистр (нет записей) — без ошибок.
4. Константы с отбором — набор выгружаемых констант не изменился.
5. Загрузка: сопоставление и создание объектов по правилам; права на чтение.
6. Формы: загрузка/выгрузка XML из формы, помещение файла (`НачатьПомещениеФайлаНаСервер`).
7. Если возможно — сравнить XML выгрузки до и после правок.
8. Поиск значений свойств объектов — через новый делегат
   `ТБ_ЗагрузкаОбъектов.НайтиЗначениеСвойстваПоНаименованию` (ранее — `НайтиПоНаименованию`
   по справочнику значений свойств): убедиться, что сопоставление значений свойств объектов
   работает как раньше.
9. Шрифты в формах `InformationRegisters/ТБ_СоответствияОбъектов/Forms/ФормаЗаписи` и
   `Catalogs/ТБ_ПравилаСопоставления/Forms/ФормаЭлемента` берутся из элемента стиля
   `ШрифтыСтиля.ЖирныйШрифт` — визуально без изменений.

## Что уже проверено статически (без базы)

Два «остаточных риска» рефакторинга ядра выгрузки закрыты проверкой по источникам:

1. **Обращение `Объект[ИмяКолонки]` в `ОбработатьОбъектПоСсылке`** (колонки берутся из
   `ВЫБРАТЬ ПЕРВЫЕ 0 *`). Проверено: все «лишние» колонки таблицы объекта — это свойства
   объекта. В частности `ВерсияДанных` документирована как свойство именно объекта
   (`СправочникОбъект.<Имя>.ВерсияДанных`, только чтение, Строка, с 8.2), а не только
   выборки. Значит доступ по имени колонки корректен.
2. **Конструкция `ВЫБРАТЬ ПЕРВЫЕ 0 *`** (пакет для построения кэша колонок). Проверено:
   конструкция рабочая и широко применяется — в основной конфигурации `пустая_для_гкс` она
   встречается 21 раз (например `CommonModules/УчетСтраховыхВзносов/Module.bsl:923`,
   `CommonModules/ПерсонифицированныйУчет/Module.bsl:1077`,
   `Documents/ОтражениеЗарплатыВФинансовомУчете2_5/ManagerModule.bsl:2784`). Менять на
   `ПЕРВЫЕ 1`/`ГДЕ ЛОЖЬ` не требуется.

**Осталось проверить только на базе:** размер пакета `ВыполнитьПакет` (по одному
`ВЫБРАТЬ ПЕРВЫЕ 0` на каждый ссылочный тип — убедиться, что пакет разбирается на полном
составе выгрузки ERP) и поведение `ПравоДоступа("Чтение", …)` в `ВыгрузитьДанныеМассиваСсылок`
как приближения прежнего `РАЗРЕШЕННЫЕ` (RLS).

## 2. Ручные правки в редакторе форм EDT (инструментом не выполняются)

Ручные правки в редакторе форм EDT, выполненные ранее, закрыты. Маркеры `SU114`, `SU115`,
`SU117`, `SU118`, `SU188` в текущем выводе `GetMarkers` отсутствуют.

**Ручных правок в редакторе форм EDT больше не требуется.**

Известный дефект инструмента (передать разработчикам Напарника): `1C_EditMetadata`
с операцией `addFormCommand` на форме без командного интерфейса падает с
«left Form structurally invalid: Form.commandInterface must be set» и откатывается —
добавить команду формы через инструмент невозможно.

## 3. Принятые решения: что НЕ правится и почему

Сгруппировано по коду проверки; в скобках — число маркеров из фактического списка (11).

- **`SU61` (3–4 маркера)** — `Подключаемый_ВыполнитьПереопределяемуюКоманду` и
  `СО_ЗаполнитьЗначенияПустыхСвойств`: имена заданы механизмом переопределения
  платформы/БСП, переименование отключит функциональность. **Решение: не править** —
  правки в коде нет.
- **`SU1` (1)** — `ПолучитьФорму` в
  `Catalogs/ТБ_СценарииЗагрузкиОбъектов/Commands/ВыполнитьСейчас/CommandModule.bsl`:
  замена на `ОткрытьФорму` меняет ветку с `ОжидатьЗавершение`. **Решение: не править.**
- **`SU11` (1)** — `&Вместо` в `CommonModules/ОбщегоНазначенияУТКлиентСервер`: тело не
  является полной копией оригинала, `&ИзменениеИКонтроль` изменит смысл переопределения.
  **Решение: не править.**
- **`SU97` (1)** — `Forms/ВыборИзЗапроса/Module.bsl`: реквизит `РезультатЗапроса`
  создаётся динамически, удаление `ЭтотОбъект.` даёт ошибку; нужно объявить реквизит
  статически в редакторе форм. **Решение: не править (требует правки формы).**
- **`SU109` (1)** — ролевая настройка «Использование» элемента формы (нужна функциональная
  опция). **Решение: принять** — осознанная логика.
- **`SU111` (2)** — условное оформление формы и реквизита динамического списка.
  **Решение: принять** — осознанная логика оформления.
- **`SU196` (1)** — имя обработки `ВыгрузкаЗагрузкаДанныхXMLСФильтрами` без префикса `ТБ_`.
  **Решение: принять** — переименование сломает внешние ссылки.

## 4. Подавление маркеров SU* через `// @skip-check` — не работает

В этой сборке EDT директива `// @skip-check <код> - <причина>` **не подавляет проверки
семейства `SU*`** — ни предупреждения, ни ошибки. Проверено экспериментально на этом проекте
(все вставки затем откачены, в коде мусора нет): размещение на уровне метода, на уровне
инструкции, на уровне всего модуля и inline; два формата кода — `SU242` и `SU:242`.
Ни один вариант маркер не снял; отдельно проверено, что `// @skip-check SU13` не снимает и
error-маркер.

**Документальное объяснение (ИТС, `edtdoc#content:158` «Настройка проверок»):** «Возможность
управления стандартными проверками реализована в версии 2021.2. К настоящему моменту только
часть стандартных проверок 1C:EDT переведена на новый механизм. Эти проверки можно видеть в
диалогах настройки проверок и в редакторе подавления проверок. Остальные стандартные проверки
выполняются, однако управлять ими нельзя». Проверки `SU*` (плагин «1С:Стандарты разработки V8») —
из неуправляемых.

**Возможные пути (на выбор, все вне правки `.bsl`):**

1. принять оставшиеся маркеры как осознанные отклонения (см. раздел «Принятые решения»);
2. закрыть вручную в редакторе форм EDT (см. таблицу выше);
3. отключить проверки целиком: `Свойства → V8 → Валидация` в контекстном меню проекта
   (для `SU*` доступно только снятие ветки «1С:Стандарты разработки V8» — теряется весь
   контроль стандартов, поэтому применять только по явному решению пользователя).

**Итог: маркеров 1С в проекте — 11 (было 312 на старте задачи), из них severity:error —
0.**
