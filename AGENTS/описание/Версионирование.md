# Версионирование расширения `ТБВыгрузказагрузка`

Канонический источник правды по версионированию расширения `ТБ_СопоставлениеОбъектов`.
Схема — общая для всех проектов workspace (`Major.Minor.Patch`, три компонента).

## 1. Версия расширения

Ведётся в `src/Configuration/Configuration.mdo`, атрибут `version`, и состоит из
**трёх компонентов**:

```
Major . Minor . Patch
```

Стартовое значение — `1.0.0` (проставлено 2026-10-09).

- **Major** — уровень релиза. Поднимается **только по явному запросу пользователя**
  при фундаментальных изменениях логики или пересборке архитектуры. Самостоятельно
  не поднимать.
- **Minor** — новая функциональность или изменение бизнес-логики.
- **Patch** — багфиксы, hotfix-ы, исправления реализации.

**Всегда три компонента** (`1.0.0`, а не `1.0`). **Один подъём версии на задачу** —
в самом конце, после обновления документации и проверки маркеров. Холостые правки
версию не двигают.

## 2. Порядок при выпуске изменения

1. Определить уровень изменения (`Major` / `Minor` / `Patch`).
2. Поднять версию в `Configuration.mdo` — **только через модель конфигурации**
   (инструмент правки метаданных, `object_name = Configuration`); файловые
   инструменты этот файл не редактируют.
3. Дописать короткую запись в `ИсторияВерсий.md`:
   версия → что изменено (1–3 предложения) → тип (фича / багфикс / рефакторинг).

## 3. Почему так

- Общее правило workspace — `Major.Minor.Patch`; схема из четырёх чисел применяется
  только в проекте `Доработки_ГКС_К` (там несколько независимых подсистем со своими
  версиями).
- В расширении `ТБ_СопоставлениеОбъектов` подсистем две, но единая сквозная логика
  («сопоставление + загрузка»), поэтому ведётся одна версия на всё расширение.
- Git-репозитория в проекте нет; история версий живёт в `ИсторияВерсий.md`.
