# Описание расширения `ТБВыгрузказагрузка`

Корневой документ описывает расширение конфигурации **`ТБ_СопоставлениеОбъектов`**
(синоним «Сопоставление объектов (ТБ)», проект EDT — `ТБВыгрузказагрузка`) как единое
целое: назначение, состав, подсистемы, ключевые механизмы и правила ведения
документации. Детальная карта объектов — в `описание/Структура.md`, хроника версий —
в `описание/ИсторияВерсий.md`, схема версий — в `описание/Версионирование.md`.

> **О названиях.** Папка проекта в workspace — `ТБВыгрузказагрузка`, а имя самой
> конфигурации расширения — `ТБ_СопоставлениеОбъектов` (префикс объектов `ТБ_`).
> В коде и метаданных фигурирует второе имя; в путях файловой системы — первое.

## 1. Общее назначение

Расширение конфигурации `1С:ERP Управление предприятием 2`
(версия `2.5.26.118`, платформа `8.3.27`, назначение `AddOn`, родительский проект
`пустая_для_гкс` — read-only) реализует подсистему **сопоставления и загрузки
объектов** из внешних источников данных в информационную базу.

Основные задачи подсистемы:

1. **Сопоставление объектов** — интерактивное и пакетное сопоставление объектов
   внешнего источника (таблица, внешний источник, COM-соединение с 1С) с объектами
   текущей ИБ по настраиваемым правилам и обработчикам.
2. **Загрузка объектов** — выполнение сценариев загрузки, создание/заполнение
   объектов ИБ по данным источника с контролем отклонений и прогрессом.
3. **Анализ загруженных данных** — сверка загруженных объектов с данными источника,
   таблица отклонений.
4. **Выгрузка/загрузка данных XML с фильтрами** — универсальная обработка
   выгрузки и загрузки данных XML с отборами.

## 2. Параметры конфигурации расширения

- **Имя:** `ТБ_СопоставлениеОбъектов`; синоним «Сопоставление объектов (ТБ)».
- **Тип:** `ConfigurationExtension`; принадлежность `Adopted` (расширение).
- **Префикс имён (`namePrefix`):** `ТБ_`.
- **Назначение (purpose):** `AddOn`.
- **Режим совместимости расширения:** `8.3.16` (`configurationExtensionCompatibilityMode`).
- **Версия платформы:** `8.3.27`.
- **Основной режим запуска:** `ManagedApplication`; назначения `PersonalComputer`.
- **Вариант встроенного языка:** русский; интерфейс `TaxiEnableVersion8_2`.
- **Версия:** `1.0.0` (см. `описание/Версионирование.md`).
- **`keepMappingToExtendedConfigurationObjectsByIDs = true`.**
- **Язык по умолчанию:** `Language.Русский` (заимствован).
- **Файл:** `src/Configuration/Configuration.mdo`.

> ⚠️ Инструменты окружения могут показывать для проекта другое значение
> совместимости; каноническим является значение из `Configuration.mdo` (`8.3.16`).

## 3. Функциональные области

### 3.1 Сопоставление объектов

Обработка `ТБ_СопоставлениеОбъектов` и ядро `ТБ_СопоставлениеОбъектов`
(общий модуль). Работа со свойствами источника данных, таблицей соответствия,
правилами сопоставления (`Справочник.ТБ_ПравилаСопоставления`) и обработчиками
заполнения (`Справочник.ТБ_ОбработчикиЗаполнения`). Результаты сопоставления
хранятся в регистре `ТБ_СоответствияОбъектов` (соответствие «идентификатор
источника ↔ объект ИБ»).

### 3.2 Загрузка объектов

Обработка `ТБ_ЗагрузкаОбъектов` и общий модуль `ТБ_ЗагрузкаОбъектов`. Выполнение
сценариев загрузки (`Справочник.ТБ_СценарииЗагрузкиОбъектов` с этапами),
настройки загрузки (`Справочник.ТБ_НастройкиЗагрузкиОбъектов`), источники данных
(`Справочник.ТБ_ИсточникиДанных`), настройки подключения
(`Справочник.ТБ_НастройкиПодключенияКИсточникам`). Состояние запусков — регистр
`ТБ_СостоянияЗагрузкиОбъектов`, загруженные данные — `ТБ_ЗагруженныеДанныеИсточника`,
доступность настроек — `ТБ_ДоступностьНастроекЗагрузкиОбъектов`.

### 3.3 Анализ загруженных данных

Обработка `ТБ_АнализЗагруженныхДанных` — сверка данных загруженного объекта
с данными источника и вывод таблицы отклонений.

### 3.4 Выгрузка/загрузка данных XML с фильтрами

Обработка `ВыгрузкаЗагрузкаДанныхXMLСФильтрами` (собственный объект расширения,
имя без префикса `ТБ_`) — универсальная выгрузка/загрузка данных XML с настройкой
отборов и дополнительных объектов.

### 3.5 Отчёты

- `ТБ_РеквизитыНоменклатуры` — отчёт по реквизитам номенклатуры (СКД,
  собственная компоновка результата).
- `ТБ_СравнениеОборотовПоСчетам` — сравнение оборотов по счетам с внешним
  источником через COM-подключение (СКД, собственная компоновка).

## 4. Подсистемы

| Подсистема | Синоним | Область |
|---|---|---|
| `ТБ_СопоставлениеОбъектов` | Сопоставление объектов | Основная подсистема: сопоставление, источники, правила, обработчики, отчёты, обработка выгрузки/загрузки XML |
| `ТБ_СопоставлениеОбъектов.ЗагрузкаОбъектов` (вложенная) | Загрузка объектов | Сценарии, настройки и состояния загрузки, анализ загруженных данных |
| `ТБ_СопоставлениеОбъектовСлужебная` | Сопоставление объектов служебная | Служебная: справочники, регистры, перечисления, картинки, элемент стиля |

Состав объектов каждой подсистемы — в `описание/Структура.md`.

## 6. Заимствованные объекты из ERP

Заимствование **широкое, но преимущественно «пустое»**: десятки справочников,
документов, перечислений, планов видов характеристик, план счетов и регистр
бухгалтерии `Хозрасчетный` заимствованы для использования в составных типах
регистров и правил. Собственных реквизитов и табличных частей в заимствованные
объекты **не добавлялось**.

Фактически доработаны (добавлены формы и/или расширенные модули) только:

- **Документы:** `ЗаказКлиента`, `ЗаказПоставщику` (формы списка документов).
- **Журнал документов:** `СкладскиеОрдера`.
- **Обработки:** `ЖурналДокументовБезналичныеПлатежи`,
  `ЖурналДокументовВнутреннегоТовародвижения`, `ЖурналДокументовЗакупки`,
  `ЖурналДокументовОтчетыКомиссионеров`, `ЖурналДокументовОтчетыКомитентам`,
  `ЖурналДокументовПродажи`.
- **Общие модули:** `МодификацияКонфигурацииПереопределяемый`,
  `МодификацияКонфигурацииКлиентПереопределяемый`, `ОбщегоНазначенияУТКлиентСервер`.

В заимствованные формы списков добавляется колонка «Загружен» (поле `ТБ_Загружен`):
запрос дополняется `&ИзменениеИКонтроль`, признак заполняется
`ТБ_ЗагрузкаОбъектов.ЗаполнитьПризнакЗагружен`. Формы других типовых объектов
дорабатываются в рантайме через `МодификацияКонфигурацииПереопределяемый`
(добавление команд «Загрузить объект» / «Загрузить объекты» и поля «Загружен из
источника»).

## 7. Ключевые механизмы

- **Типы источников данных** (`Перечисление.ТБ_ТипыИсточниковДанных`): `Таблица`,
  `ВнешнийИсточник`, `COM1C`. Для COM-источников подключение кэшируется в
  `ТБ_СопоставлениеОбъектовПовтИсп.COMСоединение` (повторное использование на сеанс).
- **Варианты заполнения реквизитов** (`Перечисление.ТБ_ВариантыЗаполнения`):
  значение, значение источника, поиск по коду/наименованию/соответствию, обработчик.
- **Обработчики заполнения** — строки кода (`Справочник.ТБ_ОбработчикиЗаполнения`),
  исполняемые на этапах «перед сопоставлением / перед обработкой / после заполнения
  строки / перед записью / после записи» (`ТБ_СопоставлениеОбъектов.ВыполнитьКодОбработчика*`).
- **Соответствия объектов** хранятся в непериодическом регистре
  `ТБ_СоответствияОбъектов` (измерения `Идентификатор`, `ИмяОбъекта`; ресурс
  `Объект` составного типа; реквизиты `ИсточникДанных`, `ПравилоСопоставления`,
  `Представление`, `ДанныеИсточника`).
- **Длительные операции.** Тяжёлые операции (загрузка объектов, поиск дублей,
  выполнение сценариев, загрузка из внешнего источника) выполняются через
  `ДлительныеОперации` + фоновое задание с индикацией прогресса, а не синхронно
  из формы.

## 8. Особенности и правила

- **Основная конфигурация `пустая_для_гкс` — read-only.** Типовые объекты
  заимствуются (`Adopted`) и правятся в расширении.
- **Расширение не наследует свойства заимствованных объектов.** При маркерах
  `SU100/SU118` сверять `descriptionLength`, `hierarchical`, `hierarchyType`,
  `codeLength` с базовой конфигурацией и приводить через инструмент метаданных.
- **Не оставлять запросы/обращения к БД в цикле.**
- **Версионирование** — `Major.Minor.Patch` (см. `описание/Версионирование.md`).
- **История и приёмы** — в `описание/ИсторияВерсий.md`, `рецепты/`, `состояние/TODO.md`,
  отчётах и планах.
