# Правила работы ИИ-агента с проектом `ТБВыгрузказагрузка`

Проектные правила для ИИ-агента **1С:Напарник** при работе с расширением
`ТБВыгрузказагрузка` (имя конфигурации `ТБ_СопоставлениеОбъектов`) в workspace
`R:\EDTProjects\GGKKSS\`.

Этот файл дополняет:
- системный промпт;
- правила уровня workspace (`R:\EDTProjects\GGKKSS\.workmate\WORKMATE.md`);
- общие правила AI-агента в workspace (`R:\EDTProjects\GGKKSS\AGENTS.md`).

Здесь фиксируются **только проектные акценты**. Архитектура и состав объектов —
в `AGENTS/описание/Описание.md` и `AGENTS/описание/Структура.md` — канонических
источниках правды.

## Базовые правила

1. **Язык**: думать и писать только на русском языке.
2. **Объекты редактирования**: менять можно **только файлы расширения** и служебные
   файлы (`AGENTS/`, `.workmate/WORKMATE.md`). Файлы основной конфигурации менять
   **КАТЕГОРИЧЕСКИ НЕЛЬЗЯ**.
3. **Изменение основной конфигурации**: если нужно — заимствуй (borrow) объект в
   расширение и редактируй там.
4. **Удаление файлов**: не удалять окончательно — переименовывать в `.bak`.

## Документация проекта

5. **В начале диалога** прочитай:
   - `AGENTS/состояние/СПИСОК_MD_ФАЙЛОВ.md` — каталог документации.
   - `AGENTS/описание/Описание.md` — главный источник правды об архитектуре.
   - По задаче: `AGENTS/описание/Структура.md`, `AGENTS/описание/ИсторияВерсий.md`,
     `AGENTS/описание/Версионирование.md`, `AGENTS/рецепты/Рецепты.md`,
     `AGENTS/состояние/TODO.md`, файлы задач/планов/отчётов.
6. **Структура документации проекта**:
   - `AGENTS/описание/` — канонические источники правды: `Описание.md`,
     `Структура.md`, `ИсторияВерсий.md`, `Версионирование.md`.
   - `AGENTS/план/` — плановые документы.
   - `AGENTS/отчёт/` — отчёты и задачи.
   - `AGENTS/рецепты/` — переиспользуемые приёмы.
   - `AGENTS/состояние/` — каталог (`СПИСОК_MD_ФАЙЛОВ.md`) и состояние (`TODO.md`).
7. **При изменении структуры или описания расширения** во время правок —
   обновляй соответствующие md-файлы в `AGENTS/` и дописывай новые в
   `AGENTS/состояние/СПИСОК_MD_ФАЙЛОВ.md`.

## Качество кода

8. После каждой своей правки **проверяй и исправляй список ошибок конфигурации**
   по изменённым объектам через `GetMarkers` (проект-уровень) и/или
   `mcp__syntax-checker__validate` (новый код).
9. Не оставляй запросы/обращения к БД в цикле.
10. Reuse-first: сначала ищи готовое в БСП через `mcp__knowledge-hub__Search_ITS`
    или `FindRelated_in_Project`, потом пиши своё.
11. Сигнатуры и поведение платформенных методов проверяй через
    `mcp__knowledge-hub__Search_Documentation` — не по памяти.

## Версионирование расширения

12. Схема — **`Major.Minor.Patch`** (всегда три компонента), старт `1.0.0`;
    канонически — в `AGENTS/описание/Версионирование.md`. Кратко:
    - версия расширения в `src/Configuration/Configuration.mdo` — три числа;
    - `Major` — только по явному запросу пользователя; `Minor` — новая
      функциональность/изменение логики; `Patch` — багфиксы;
    - **один подъём версии на задачу**, в самом конце, после обновления
      документации и проверки маркеров; холостые правки версию не двигают.
13. Порядок при выпуске: (1) поднять версию в `Configuration.mdo`;
    (2) дописать короткую запись в `AGENTS/описание/ИсторияВерсий.md`
    (версия → что изменено → тип).
14. Версия в `Configuration.mdo` меняется **только через модель конфигурации**
    (инструмент правки метаданных, `object_name = Configuration`) — файловые
    инструменты этот файл не редактируют.

## Ветка `workmate` и автопуш

15. **Вся работа ведётся в ветке `workmate`**, а не в `main`. Ветка создана от `main`
    и запушена в `origin`; `main` не трогаем — она остаётся точкой сравнения.
16. **В конце каждой задачи** (в том числе когда версия не поднималась — правки кода,
    документации `AGENTS/`, `.workmate/WORKMATE.md`) изменения фиксируются одним
    коммитом и отправляются в `origin/workmate`. Промежуточные правки внутри задачи
    отдельными коммитами не дробим.
17. **Порядок автопуша** (репозиторий `https://github.com/ka4iboss/vigruzkazaguzka`):
    - прочитать токен из файла `C:\Users\Origi\.workmate\git-token` — он лежит вне
      проектов и в репозиторий не попадает;
    - добавить **именованный** временный remote с токеном:
      `git remote add auth https://ka4iboss:<токен>@github.com/ka4iboss/vigruzkazaguzka.git`
      (именно именованный: при push в URL токен печатается в вывод инструмента);
    - `git push auth workmate`;
    - затем `git ls-remote auth` и **сверить SHA** с локальным `HEAD` — код возврата
      push'а в этом окружении не является доказательством успеха;
    - удалить временный remote `auth`, чтобы токен не остался в `.git/config`.
18. Автор коммитов берётся из глобального `~/.gitconfig` (`ka4iboss`), отдельно
    настраивать не нужно.
